Project case study

5K Preparation
Knowledge Base

I turned scattered training information into a structured website that helps a runner move from planning to race day without searching through disconnected notes and sources.

1
Project type
Information architecture
My role
Research, structure, publishing
Tools
Markdown, Quartz, GitHub
Status
Live
Visit live project ↗ Read the process ↓
1

Overview

The problem

Useful 5K advice is easy to find, but it is often spread across articles, videos, training plans, and personal notes. That makes it difficult to understand what matters first and how the pieces connect.

I built one organized resource where readers can review training, recovery, nutrition, strength work, and race preparation in a clear sequence. The goal was not to create another list of links. It was to make the information easier to navigate and use.

2

Process

How I approached it

1

Define the reader’s path

I organized the content around the decisions a runner makes: choosing a plan, completing workouts, supporting recovery, and preparing for race day.

2

Group related information

I separated large topics into focused pages and used internal links so readers could move between connected ideas without losing context.

3

Publish and verify

I wrote the pages in Markdown, generated the site with Quartz, deployed it through GitHub Pages, and checked the live navigation after publishing.

3

Decisions

Key project decisions

A

Structure before decoration

I focused first on page hierarchy, labels, and internal links because a knowledge base is only useful when information is easy to locate.

B

Short, focused pages

Breaking broad subjects into smaller pages made the material easier to scan and reduced the amount of information shown at one time.

C

Simple publishing workflow

Markdown and GitHub made it practical to revise the content, track changes, and publish updates without rebuilding every page manually.

4

Result

What the project demonstrates

  • Information architecture

    Turning a broad subject into a navigable hierarchy of useful pages.

  • Technical documentation

    Writing concise content with consistent headings, labels, and links.

  • Version control

    Using Git and GitHub to manage revisions and maintain a published project.

  • Deployment

    Making the completed work publicly available through GitHub Pages.

5

Reflection

What I learned

The most important lesson was that organization is part of the user experience. Accurate information is not enough if readers cannot quickly understand where they are or what to read next.

A future update could add a clearer beginner path, a progress checklist, and more testing with users on smaller screens. Those improvements would make the knowledge base more useful without changing its core structure.
